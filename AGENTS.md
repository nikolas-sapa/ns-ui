# AGENTS.md — working inside this repo

This is for an agent editing ns-ui itself. If you're an agent trying to *consume* a component in
some other project, you want `https://design.helpmarq.com/llms.txt` instead (or the README).

## Structure

Each component is a self-contained folder: `registry/{core,loud}/<name>/` with:

- `component.tsx` — the actual component. `"use client"`, zero or minimal deps, tokens not hex.
- `demo.tsx` — the preview render used by `/preview/<name>` and the screenshot verifier.
- `meta.json` — the single source of truth: `name`, `title`, `description`, `collection`, `tags`,
  `instruction` (a rich paragraph describing behavior — read by `scripts/build-llms.ts`), `dependencies`.
- `screenshots/` — generated by `npm run verify`, not hand-authored.

`core` = Geist-dark restraint (42 components). `loud` = deliberately flashy showcase (8). Collection
is decided at creation time and drives folder placement, not a runtime flag.

## meta.json is the source of truth — never hand-edit generated files

`registry.json` (root) and `public/r/<name>.json` are generated from `meta.json` sidecars by
`npm run registry:build` (`scripts/build-registry.ts`). `public/llms.txt` and `public/llms-full.txt`
are generated the same way by `scripts/build-llms.ts` (chained into the same `registry:build` script).

Never hand-edit `registry.json`, anything under `public/r/`, or `public/llms*.txt` — edits will be
silently overwritten on the next build. If something in the generated output is wrong, fix
`meta.json` (or the component source, for prop signatures) and rebuild.

`public/r/` is gitignored — it's regenerated at build time (locally and on Vercel). `public/llms.txt`
/ `public/llms-full.txt` are NOT gitignored; they're small enough to commit, and get regenerated on
every build anyway so a stale commit self-heals on the next deploy.

## Registering a component

Adding a component isn't done until it's wired into `registry/index.tsx` — the central lazy demo
map (`name -> lazy(() => import(...))`). A component with a folder but no entry there won't render
on `/preview/<name>` or pass verification. This is the one place that isn't derived from `meta.json`
and has to be hand-edited per component.

## The token/theme rule (hard constraint, not a suggestion)

Colors come from CSS custom properties already in scope — `--background --foreground --muted
--border --accent` — never hardcoded hex, in component markup OR in canvas/SVG draw code. This
broke the light theme across the whole registry once already. If a component derives ink for a
`<canvas>`, read it via `getComputedStyle` at mount/theme-change, don't bake in a color literal.
Both light and dark themes must render correctly — verify both, not just whichever your terminal
defaults to.

## Build & verify gate

```bash
npm run registry:build   # meta.json -> registry.json, public/r/*.json, public/llms*.txt
npm run typecheck        # tsc --noEmit, must be clean
npm run verify           # requires dev server running; screenshots every component x theme x state,
                          # hard-fails on console errors, blank renders, or malformed meta.json
```

A component (or a change to one) isn't done until `npm run verify` passes and the idle/default-state
screenshot has actually been looked at — that's the state the owner judges first and hardest.

## Prop-signature extraction (`scripts/build-llms.ts`)

`build-llms.ts` scans each `component.tsx` for its exported prop shape using bracket-balanced text
scanning (no AST/parser dependency, matching `build-registry.ts`'s plain-node style). It recognizes:
named `export interface FooProps` / `export type FooProps`, inline destructured object types on
`export function Foo({ ... }: { ... })`, and `forwardRef<Handle, Props>(...)`. If you introduce a
prop-shape pattern the scanner doesn't recognize, it will print a loud `WARNING` naming the
component and emit `props: (unresolved — read the source)` in the output rather than silently
dropping the component's props — if you see that warning, either simplify the prop declaration to
one of the recognized shapes or extend the scanner, don't ignore it.
