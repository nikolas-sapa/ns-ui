# Registry rename: execution plan

Companion to `docs/rename-map.tsv` (223 rows). **Proposal only** — nothing under
`registry/` has been touched.

The map renames 222 of 223 components. `scroll-caliper` is already
`<type>-<trait>` and keeps its slug.

---

## 1. What a slug actually is, in this repo

A slug is not one string in one place. It is simultaneously:

| Role | Where | Derived or authored? |
|---|---|---|
| Folder name | `registry/{core,loud}/<slug>/` | authored |
| Registry item id | `meta.json` → `"name"` | **authored** — `build-registry.ts:20` reads `meta.name` verbatim |
| Install target path | `components/ui/<slug>.tsx` | derived from the **folder**, `build-registry.ts:28` |
| Demo import key | `registry/index.tsx` | derived from the folder, `build-index.ts:18-28` |
| CSS scope prefix | `.ns-<slug>` inside `component.tsx` | authored |
| Curation / ordering entries | `lib/featured.ts`, `lib/component-order.json` | authored (order is generated, see below) |
| Search vocabulary | `lib/search-synonyms.ts`, `lib/search-categories.ts` | **hand-curated** |
| Prose cross-reference | other components' `instruction` / `useWhen` | authored |

**The trap:** `name` in `meta.json` is authored while `target` is derived from
the folder. Rename the folder and forget `meta.json` and you get a registry item
called `bough-index` that installs to `components/ui/tree-box-drawing.tsx`. It
builds, it typechecks, and it is wrong.

## 3. Screenshots

**Verified: screenshots move with the folder and stay valid.**

Every component folder contains `screenshots/` with `{dark,light}-{default,hover,focus,press,open}.png`
(223 `screenshots/` directories confirmed). They are addressed by relative path
from the folder, so `git mv registry/core/bough-index registry/core/tree-box-drawing`
carries them along. No re-capture is needed.

**But `recordings/<slug>.mp4` is different** — 33 videos sit in a flat
top-level `recordings/` directory keyed by slug, outside the component folder.
They do not move with the rename and must be renamed alongside it.

`public/posters/` is generated from `lib/featured.ts` plus the folder
screenshots, so it self-corrects on rebuild — provided `featured.ts` was updated.

## 4. Execution sequence

Do it as one atomic change on a branch. A half-applied rename is worse than none.

1. **Branch.** `git checkout -b rename/descriptive-slugs`
2. **Move folders.** `git mv registry/<col>/<old> registry/<col>/<new>` for all 222.
   Use `git mv` so history follows and the screenshots ride along.
3. **Rename recordings.** `git mv recordings/<old>.mp4 recordings/<new>.mp4` (33).
4. **Rewrite `meta.json` `"name"` AND `"title"`** in each moved folder, from the
   `new_slug` and `new_title` columns. Both are authored and both are copied
   verbatim into `registry.json`. 223 names, 222 titles.
5. **Rewrite `.ns-<old>` → `.ns-<new>`** across `component.tsx` / `demo.tsx`
   plus the one occurrence in `intent-coil/meta.json` (94 occurrences,
   14 files). All-or-nothing per component.
6. **Rewrite authored slug lists**: `lib/featured.ts`, `lib/search-synonyms.ts`,
   `lib/search-categories.ts`, and `lib/component-order.json` — the last one by
   mapping old→new **in place, preserving array order**. Do not regenerate it
   (§5).
7. **Rewrite prose cross-references** in every `meta.json` `instruction` /
   `useWhen` (209 occurrences) and `component.tsx` comments (75).
8. **Rewrite `app/`, `cli/`, `scripts/`, `workflows/`** occurrences.
9. **Rewrite `README.md`, `AGENTS.md`, `CONTRIBUTING.md`, `docs/`, `wiki/`.**
10. **Do not touch** anything in §2d.
11. **Rebuild, in this order:**
    ```
    npm run registry:build     # index → registry.json → llms → autoplay → posters → mcp
    npm run typecheck
    npm run verify
    ```
    `pretypecheck` and `preverify` both run `registry:build` again; that is fine
    and idempotent.

    **Do NOT run `npm run order:build`.** See §5 — it would either destroy the
    curated ordering or hard-fail.

    Update, post-29b5364: `scripts/build-order.ts` now follows rename chains
    (`--diff-filter=AR -M`) and reconstructs true creation order across any
    number of renames, verified byte-identical against the hand-remapped file.
    A future mass rename can run `npm run order:build` directly — no more
    hand-remapping `lib/component-order.json`.
12. **Verify** (see §6), then commit as one commit.

Steps 2-9 are best done by a single script driven directly off
`docs/rename-map.tsv` rather than 222 hand edits.

## 5. Known hazards

- **`lib/kind.ts`'s doc comment is now false.** It states the names are
  metaphorical on purpose and that "renaming 223 components would break every
  install anyone has already run." That premise is exactly what this change
  overturns. Rewrite the comment. `kindOf()` itself needs no code change — it
  reads tags, not names.
- **`lib/search-synonyms.ts` premise weakens, but do not delete it.** Its header
  says it exists *because* the names are metaphorical. After the rename most
  entries become redundant with the slug itself. Trimming it is a separate,
  reviewable change — out of scope here. Update the slugs and leave the file.
- **`order:build` is broken by any folder rename — this is the sharpest hazard
  in the whole change.** `scripts/build-order.ts` derives the newest-first order
  from `git log --reverse --diff-filter=A --name-only -- registry/*/*/meta.json`,
  i.e. "the first commit that added this `meta.json`". After a mass `git mv`,
  every component's `meta.json` sits at a brand-new path, and one of two things
  happens, neither good:
  - Git's rename detection (`diff.renames` defaults to true) classifies the
    moves as `R`, not `A`. `--diff-filter=A` then yields nothing for the renamed
    paths, `ordered.length < onDisk.length` trips the guard at
    `build-order.ts:56`, and the script exits 1: *"refusing to overwrite"*.
  - If rename detection does not fire (too many simultaneous moves can exceed
    the rename limit), all 223 are recorded as added in the single rename
    commit, every creation timestamp collapses to that one commit, and the
    curated newest-first order is silently flattened.

  **Mitigation:** do not regenerate. Rewrite `lib/component-order.json` in place
  by mapping old→new slug while preserving array position. The order is a
  committed snapshot by design (see the file header), so an in-place rewrite is
  legitimate. `order:build` only becomes usable again once the rename commit is
  far enough back that it is re-run with `--no-renames`, or the script is taught
  about the rename — either is a separate change.
- **Word-boundary substitution is not safe naively.** `tear-tab` is a substring
  of nothing, but `wet-ink` appears inside `.ns-wet-ink-caret`, and
  `hold-to-confirm` appears inside prose sentences. Match on `\b<slug>\b` and
  apply the longest slug first so no slug is rewritten inside another.
- **Two slugs deliberately fail the tag assertion.** `not-found-postmark`
  (`dead-letter`) and `not-found-knockout` (`knockout-404`) use the type word
  *not-found* where the tags say `404` / `error-page`. This is intentional:
  "not found" is what a developer searches. Either accept it or add `404` to a
  synonym entry.

## 6. Verification checklist

Green build is not proof. Check all of these:

- [ ] `npm run typecheck` clean
- [ ] `npm run verify` clean
- [ ] `registry.json` has 223 items and **zero** old slugs:
      `grep -c -F -f <(cut -f1 docs/rename-map.tsv | tail -n +2) registry.json` → 0
- [ ] `meta.title` == the `new_title` column for all 223 items
- [ ] Repo-wide sweep: no old slug survives outside §2d. Build the old-slug list
      as `cut -f1 docs/rename-map.tsv | tail -n +2 | grep -v '^scroll-caliper$'`
      — `scroll-caliper` is in both columns and would report as a false
      positive. Match on `\b<slug>\b`, longest slug first (§5), or short slugs
      like `wet-ink` and `worn-path` will hit inside ordinary prose and the
      sweep gets ignored as noisy
- [ ] For every item: `meta.name` == folder name == `files[0].target` basename
- [ ] 223 `screenshots/` directories still present after the moves
- [ ] `recordings/` contains 33 `.mp4`s, all matching new slugs
- [ ] `lib/featured.ts` — all 36 slugs resolve to a real item (a stale one is
      silently dropped, so count the rendered rail, don't trust the build)
- [ ] `lib/search-synonyms.ts` — every value slug resolves; assert in a script,
      this file fails silently by design
- [ ] `lib/component-order.json` has 223 entries and the *same positional order*
      as before the rename (diff it against the old file mapped through the TSV;
      it must be identical, not merely 223 long)
- [ ] Spot-check three renamed components in `npm run dev` for missing styling
      (the `.ns-` prefix risk) — pick from the 13 files in step 5
