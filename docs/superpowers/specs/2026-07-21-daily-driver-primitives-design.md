# Round 5 — daily-driver primitives

The registry is 50 showpieces and zero plumbing. Someone installs `particle-hero`, then
goes to shadcn for everything an app is actually made of. This round adds the three
missing primitives, each carrying one behavior the alternatives don't have.

Not building a tooltip: smallest payoff, worst accessibility-per-hour, and it is
physically too small to read on a landing card.

## Hard constraints for all three

- Collection `core`. Folder `registry/core/<name>/` with `component.tsx`, `demo.tsx`,
  `meta.json`. `screenshots/` is generated by `npm run verify`, never hand-authored.
- **No `<canvas>` in any of the three.** CSS and SVG only. That deletes the entire
  historical bug class (token-hardcoding in draw code, backing-store sizing, DPR,
  zero-size seeding) rather than re-litigating it three more times.
- Colors come from tokens in scope — `--background --foreground --muted --border
  --accent --surface` — via Tailwind classes (`text-muted`, `border-border`,
  `bg-surface`). No hex literals anywhere. Must read correctly in light and dark.
- Zero runtime dependencies. `"use client"` at the top.
- `prefers-reduced-motion: reduce` must degrade to a still, correct, usable state —
  never to a broken or invisible one.
- Every event listener, observer and timer is removed on unmount.
- The default (idle, no-input) screenshot must explain the component with no caption.
  That is the state judged hardest.

### verify.ts landmines

`scripts/verify.ts` hovers, presses and focuses the **first visible** element matching
`button, a, [role=button]` in DOM order, and hard-fails if the hover screenshot is
byte-identical to the default. So:

- The first interactive element in DOM order must be genuinely hoverable — not
  `inert`, not covered by an overlay. Playwright's actionability check throws and
  crashes the run otherwise.
- That element must have a visible hover state.
- Dark and light default screenshots must differ, or the gate fails the component.

## 1. `emerge-dialog` — the modal

A modal built on the native `<dialog>` element with `showModal()`. Focus trap, inert
background, Escape-to-close, top-layer stacking and `::backdrop` all come from the
platform; there is no reason to reimplement any of it, and the native version beats a
hand-rolled focus trap on the edge cases.

**The twist: the dialog emerges from the control that opened it.** On open, the
trigger's bounding rect is measured and the dialog animates from that rect to its
final rect (FLIP — one `transform`, no layout thrash), and on close it returns into
the trigger. The user never loses the thread of what they clicked. Radix and shadcn
both fade from nowhere.

- Trigger rect measured at open time, not at mount — it moves on resize and scroll.
- No trigger available (opened programmatically) falls back to a centered scale-in.
- Reduced motion: no morph, plain instant open. Still fully functional.
- Backdrop dims with a token color, no blur (blur costs a compositor layer and reads
  as generic).

**Demo:** renders **open at rest** — a closed modal is an empty page and fails the
self-explanation bar outright. The `<dialog>` markup must come **before** the trigger
button in DOM order so verify.ts hovers a live in-dialog button and not the inert
trigger behind it. `autoplay` mode `press` targeting the dialog's own close control,
so the card shows the return-to-origin motion.

## 2. `fallow-panel` — the empty state

The screen a list shows before it has anything in it. Fallow: land left unplanted, on
purpose, waiting.

**The twist: the boundary is alive.** An SVG dashed outline that drifts slowly (animated
`stroke-dashoffset`) — the panel reads as a plot marked out and not yet filled. On CTA
hover the outline contracts toward the button, so the affordance points at itself.

Deliberately the plainest of the three. Content is a headline, one line of muted copy,
and one accent CTA. Does not use ghost content rows — that silhouette belongs to
`develop-skeleton`, and two components that look alike at rest is worse than either
being dull.

Reduced motion: outline static, no drift, no contraction.

## 3. `develop-skeleton` — the loading state

A wrapper, not a grey rectangle: `<DevelopSkeleton loading>{children}</DevelopSkeleton>`.
While loading it renders placeholder blocks matching the children's layout; when
`loading` flips false the blocks **develop** into the real content — photographic
resolve, blocks settling to the real text metrics — instead of the standard
swap-and-flash. shadcn ships a div with a pulse; the useful part is the transition
nobody writes.

- The shimmer is a token-derived sweep, not the cliché white-to-grey gradient.
- Blocks are laid out from a simple declarative prop (line counts / widths), not by
  measuring children — measuring an unmounted subtree is a trap.
- Reduced motion: no shimmer, no sweep, plain static blocks, instant swap.

**Demo:** loops loading → loaded → loading so the card is alive, and rests in the
loading state so the default screenshot reads unambiguously as "this is loading".

## Sequencing

Three folders, three independent authors, no shared file — `registry/index.tsx` is
generated by `scripts/build-index.ts` and gitignored, so there is nothing central to
serialize on. Then one gate, run once, by hand:

```
npm run registry:build && npm run typecheck
npm run build && npx next start -p 3410
BASE_URL=http://localhost:3410 node scripts/verify.ts <name>
```

Production build only. On a shared dev server Turbopack serves corrupted chunks on
15-50% of loads and an unhydrated component looks identical to a catastrophically
broken one.
